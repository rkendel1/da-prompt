# CLAUDE.md

da-prompt is a zero-dependency Node.js (>=20, ESM) software factory: a planner, role agents,
verification/feedback loop, completion checklist and delivery, with a web UI.

## Commands
- `npm test` — full suite (uses offline agents, no network or API key needed)
- `npm start` — server on PORT (default 4747)
- `npm run factory -- "idea"` — headless run

## Dev path (works without da-prompt, a backend or an LLM)
- `npm run check` (static checks) · `npm run build` (package/entry/import smoke) · `npm test` · `npm run validate` runs all three.
- The CLI (`src/cli/`) is a client of the one backend: add a capability to `src/server.js`/`src/factory.js` first, then a command in `src/cli/commands/`. Never give it a second run store or orchestration loop.

## Conventions
- No runtime dependencies. Use `node:` built-ins and global `fetch`.
- All agent file access goes through `Workspace` in `src/sandbox.js`; never bypass it.
- Anything persisted or shown in the UI that might contain secrets goes through `redact()`.
- Every new factory behaviour should be covered in `test/factory.test.js` via the offline provider.
- The UI (`public/`) is plain HTML/CSS/JS; escape every dynamic string with `esc()`.
- Provider calls go through `src/providers/http.js` (node:http, no fetch headers timeout — local models are slow).
- New provider presets go in `PRESETS` in `src/providers/registry.js`; cover new adapters with `test/mock-llm.js`.
- CLI output: human text through `out.print/info`, machine output through `out.data` (so `--json` stays one clean document); errors are `CliError(message,{code,hint})` with the documented exit codes. Every new command needs a test in `test/cli*.test.js` (in-process `cli()` against `startBackend()` from `test/cli-helpers.js`).
- Offline agent output lives in `templates/offline-app/*.tpl`; keep its tests passing.

## Lessons
- Agent engines (`src/engines/`): `builtin` is the default and must keep working with no extra packages; optional engines (today `fx`) are installed under `<data dir>/engines`, never into this repo's dependencies, and take the SAME `runAgent` arguments/result. Their tools must go through `execTool`/`Workspace`, credentials may only reach them as env var names, and a run keeps the `engine` it started with. Test with an injected fake module (`cfg.engineModules`), as in `test/engines.test.js`.
- Local models and fx (`src/providers/tooltext.js`, `src/providers/bridge.js`, `normalizePlan`/`normalizeToolInput`/`compactHistory` in `src/agents.js`): be liberal in what a model may send (text plans, qwen3-coder `<function=…>` XML, raw newlines in JSON, `bash`/`file_path` aliases) and strict in what is executed: aliases only ever map onto the five real tools, and repaired plans still go through `validatePlan`. fx never talks to a provider directly: its model client is pointed at the loopback bridge, which answers through `provider.chat()` (so num_ctx, retries, JSON tool mode and text recovery apply) and sends SSE headers at once plus keepalives, because fx 0.1.2 aborts a request with no response headers after 120 s. The bridge never makes its own outbound request and the provider key never reaches fx (it gets a one-off bridge token by env var name). Test with `test/local-inference.test.js` (an HTTP-speaking fake fx); the real package can be checked by hand with `npm run engine:install -- fx`.
- AppPort-native generated apps (`src/appport.js`, `templates/stack.json`, `templates/offline-app/src/appport.js.tpl`, `templates/offline-app/variants/catalog/`): new apps expose capabilities through the PUBLISHED @appport/* packages (pinned in the JSON file, the single source; never file:/link: deps, never copied source). Capabilities call the app's own store; writes need a permission; only opted-in capabilities are registered. The gate (`checkAppPortConformance`, checklist item `appport`) is behavioural and never mutates the app; the factory itself stays dependency-free (it speaks the wire protocol, it never imports @appport). The only opt-out is `settings.appportException` with a reason. Generated apps install from the registry through `npm_config_cache` = `cfg.npmCache` (tests share one cache via `test/setup-env.cjs`).
- Stack profiles (`src/stack.js`, `templates/stack.json`, `templates/offline-app/variants/{feltdb,releases}/`): stack.json is the ONE mapping (packages, versions, requires, status, rules, blockers); never pin a stack package anywhere else. Only verified components are `supported`; unsupported ones (AuthBoundry, AppPort Services, AppBoundry) fail in `resolveStack` with their blocker and next step: no placeholder adapter, no app-owned substitute authorizer for Services. FeltDB 0.11.9 does not enforce its single-writer lock (the app must, with its own lock file) and posts telemetry unless `FELTDB_TELEMETRY=0` (`Factory.toolEnv()` sets it for everything the factory runs; generated apps document it). Generated apps read `DATA_DIR`; previews and gates get throwaway folders under the workspace's `.home`. A FeltDB app's data model is `feltdb.flow` (project root): the app validates it, deploys it (`deployFlowSpec`, never `allowDestructive`), requires the active contract hash to equal the flow's, and checks every record against it in `src/flow.js`, because FeltDB 0.11.9's local runtime accepts records that violate the deployed model. Never describe that check as FeltDB's. Server shutdown must call `closeIdleConnections()` or `store.close()` never runs. `npm run prove:stack` is the end-to-end proof (report in docs/stack-proof.md).
- `node --test <dir>/` does not accept a directory on Node 22; use a glob (`test/*.test.js`) or no argument.
- `safeEnv()` drops `NODE_TEST_CONTEXT`: inherited, it makes a nested `node --test` skip itself and exit 0. Do not delete it in test files instead; that collapses the runner's per-test reporting.
- `safeEnv()` must drop the whole `GIT_CONFIG_*` family, not just the `*KEY*` entries, or `git` breaks in agent shells.
- Existing-project work lives in `src/project.js` (sources, inspection, baseline, changes) and `src/publish.js` (push + PR); factory behaviour is branched on `isExisting(run)`, not duplicated.
- Operating surface: `src/settings.js` (saved settings + precedence), `src/health.js` (real probes), `src/pax.js` (PAX adapter), `src/evidence.js`, UI in `public/ops.js`. Every setting must map to a field the runtime reads; PAX output is `run.pax` and must never feed the verdict, checklist or readiness.
- Browser tests: open the page on the target hash instead of re-navigating to the same route (a hashchange re-renders New Run and swaps the form under your `fill`).
- Tests that depend on provider/GitHub/PAX state must clear the machine's env first (`ANTHROPIC_API_KEY`, `GITHUB_TOKEN`, ...) and give each server its own `env` (the registry reads it lazily).
- `node --check` treats `.js` as CommonJS when no `package.json` with `"type":"module"` is above it; fixtures that test `scripts/check.mjs` need one.
- The factory's per-command timeout (`commandTimeoutMs`, 3 min) is shorter than this repo's full `npm test`; when da-prompt works on itself raise it (`da-prompt config set commandTimeoutMs 900000`) or the baseline `npm test` reports a timeout.
- In CLI tests, `main()` reads `io.env`/`io.cfg`; state helpers must be passed `ctx.env` (a `writeState()` without it wrote to the real HOME once).
- Terminal (`src/terminal.js`, `src/terminal-pty.py`, `public/terminal.js`, `/api/terminal`): a privileged host-shell feature. Never route it through agents/providers/runs; never build a shell string (argv arrays + raw PTY bytes); keep every route behind `terminalGuard` (admin + Origin/Host checks) and the session principal; never log or persist terminal I/O or environment.
- Terminal tests: the typed command line is echoed by the PTY, so wait for output with a leading newline (`/\nMARK/`), not for the bare word. Use `/bin/bash` in UI tests (dash has no history); a test must never leave `sleep` children behind (they keep the test runner's pipes open and the run hangs).
- `req.on('close')` does not fire for a dead socket once the request body was read; SSE cleanup must also listen on `res`.
- `npm test` preloads `test/setup-env.cjs`, which strips FACTORY_*/DA_PROMPT_*/PORT/HOST/keys/tokens from the environment (except `DA_PROMPT_PAX_BIN`).
- Projects (`src/registry.js`, `public/projects.js`, `/api/projects/<prj_id>`): the registry is the one project system; features take a `projectId` and obtain the workspace only through `registry.locate()` (re-validates, refuses archived/missing/inaccessible/attention). Never store a path or directoryId as a project's identity, never auto-follow a folder that holds a different repository, never delete files on removal. Keep conflict checks inside the serialized `mutate()`.
- Registry tests: two temp repos with identical content and commit time get the same first-commit hash and look like the same repository; give them different messages.

- Chat and backlog (`src/chat.js`, `src/chat-context.js`, `src/tasks.js`, `src/jsonstore.js`, `public/chat.js`, `public/backlog.js`): chat is advisory and has no tools; a conversation is bound to one `projectId` (or to none: a general chat) for life, created lazily on the first message from the UI; what is sent to the model is the per-conversation `context` (switchable `sources` + pinned `notes`, ids stable across reads), never more than the user left ticked; context is retrieved server-side via `registry.locate()`, bounded and recorded on the message. The backlog order is the single `order` array in `tasks.json` plus a `rev`; never add a second priority field, never reorder on status change. Only `POST /api/tasks/<id>/start` may create a run from a task, and a run finishing never completes a task. Tests: `ChatFake` and `startWorkBackend` in `test/work-helpers.js`.
- `shutdown()` in `ChatService` runs before the server closes: interrupted responses are finalized as retryable errors, not left `streaming`.

- Diagnostics (`src/diagnostics.js`, `src/contract.js`, `src/bench.js`, `scripts/bench.mjs`): observation only. Records hold identifiers, timings, counts, a failure kind and a scrubbed short message; never prompts, file contents, replies, headers or keys. They must not feed decisions, retries, verification or delivery, and a failed write must never fail a call. Missing token counts are "unavailable", never 0. `describeInference` / `da-prompt diagnostics` are offline: no network, no model call; live checks stay behind `providers test`. A new tuning option needs a row in `settingsTable` for BOTH engines (supported / fixed / unsupported / not-applicable). The benchmark's `--live` mode is never used by tests; mock reports measure nothing about a model.
- `redact()` only knows common key shapes. Text that is stored or shown after a provider error goes through `Factory.hideSecrets()` too (exact configured credential values).
- Replay and contract tests (`test/replay*.js`, `test/provider-contract.test.js`, `test/architecture.test.js`, `test/security-contract.test.js`): scripted replies through the REAL factory; never fake verification or delivery, never give a fixture a way to change production policy. Every new test file that uses mock servers calls `blockNetwork()` from `test/offline-guard.js`. Sentinel secrets must be random-looking (no ordinary 8-character words) and are checked by 8-character windows, because truncation can leave half a key. Architecture rules read `code()`/`imports()` (comments and string contents removed), never raw grep.
- CI (`.github/workflows/ci.yml`, `scripts/ci-summary.mjs`, `test/ci-workflow.test.js`): reuse package scripts; no `continue-on-error`/`|| true` on a validation step; pipe test output through `tee` only under `shell: bash` (pipefail); `fail-fast: false`; browser tests must RUN in CI (the summary step fails the job on a "Playwright is not installed" skip). A test must not depend on the machine it runs on: no assumption that an Ollama is running (the default provider differs), that `os.tmpdir()` is outside the data dir, or that git does no background maintenance (fixture repos run with `gc.auto=0 maintenance.auto=false`).

- Model routing and results (`Factory.routeFor`, `src/performance.js`, `repairPlan`/`standardPlan` in `src/agents.js`): a run's planner, agent model, `roleModels` and `retryModel` are validated in `resolveModelChoice` exactly like the agent model; each task attempt stores `attempt.model`, and that record (plus diagnostics calls) is the only source for "which model did what". Performance is observation only, like diagnostics: it must never feed routing, retries or verification. Older attempts have no `model` and are attributed to the run's agent model and counted as `inferred`, never silently. `src/factory.js` must not contain the word "fallback" (architecture guard), hence `settings.standardPlanOnFailure`.
- A new app's workspace lives under the data folder, which by default is inside this repository: `execute()` seeds a stub `package.json` so npm never resolves to an outer project (an early `npm test` used to run da-prompt's own suite and time out). A planned output of `package.json` is therefore always "present"; check it with a command instead.
- Agent loop for weak tool callers (`runAgent`, `filesFromReply` in `src/agents.js`): code blocks under a path line become `write_file` calls that go through `execTool` like any other (nothing else in a reply is ever executed; shell blocks never are); tool-less narration ends the attempt after 6 replies, or after 3 hands it to verification only when the agent did work AND the task has verify/outputs, with `result.implicit` and a summary that says it was not formally completed. Keep regex literals in `src/agents.js` free of quote and backtick characters (use \x22 \x27 \x60): the architecture tests strip strings with a simple tokenizer.
